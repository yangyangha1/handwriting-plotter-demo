HWPlotter v0.7 图片→笔顺→矢量复刻专项核查

目标：普通手写文本照片/扫描件，不使用方格输入；保留轻微连笔、相似字距/行距；按图片证据恢复物理书写顺序；低置信时排除并要求重写。

一、已实现
1. 普通多行手写图片 OCR：PP-OCRv5 server 检测/识别，方向、去畸变、文本行方向开启。
2. OCR 行四点透视矫正，不要求水平扫描。
3. 自然字距切分：墨迹投影 + 动态规划 + 软字符宽度先验，不要求方格。
4. OCR 标签只读：错误样本只排除，不允许人工改字；写入 rewrite_required.txt。
5. 页面几何保持：不再 tight-crop 后丢空白；完整 OCR 字符单元 letterbox，并反变换回原字符单元。
6. 每字原始四点 polygon 保存，页级 SVG/G-code 用透视映射恢复位置、倾斜、字距与基线。
7. Facsimile：标准 MMH 仅作语义/方向先验，墨迹逐笔分配、骨架中心线恢复、局部宽度恢复。
8. 单字内部轻微连笔：canonical stroke 保留供训练；物理 pen_down_groups 合并供写字机连续执行。
9. 跨字轻微连笔：自动检测细跨界墨迹，保存为 transition trajectory；从前后单字训练 crop 中剥离，防止污染字形模型；页级输出重新接回。
10. 笔顺推断：标准笔顺 + 可选草书/行书变体 + 图片局部异序候选 + 端点距离 + 墨迹连续性评分。
11. 草书/行书局部异序：自动搜索最多两次相邻换序形成的候选；可通过 cursive_orders.jsonl 增加经过校验的变体。
12. 时序置信门控：stroke_order_confidence / score_margin / ambiguous；歧义样本自动拒绝并要求重写，不进入样本库与训练。
13. SVG 局部笔宽：按恢复的 width 逐段输出不同 stroke-width。
14. G-code：按推断 stroke_order 和 pen_down_groups 执行；跨字 connector 可在端点兼容时连续落笔，不人为抬笔。
15. 页级输出：page_vectors.svg + page_vectors.gcode。
16. GUI：增加“笔顺/连笔”显示，错误仍只允许排除重写。

二、不能声称“数学上完美”的部分
静态图片没有时间维度。若两种不同书写顺序最终产生完全相同的墨迹图，任何纯静态图算法都无法唯一判断真实时间顺序。当前实现采用多先验评分和置信门控；无法高置信判定时拒绝样本，不伪造答案。

三、草书边界
轻微连笔、行书式并笔、局部异序已进入正式链路。高度简化的重草书可能出现 canonical stroke 被省略、重构或完全变形，此时仅依赖 MMH canonical 仍不足。公开的大规模草书图片数据多为静态字图；真实时间轨迹库（如 CASIA 在线手写库）具有授权条件，不能直接随工程打包。工程已留出 cursive_orders.jsonl 变体接口；重草书若要进一步提升，应使用合法取得的在线轨迹数据训练时序先验。

五、当前结论
对“普通手写文本照片 + 轻微连笔/行书”的目标链路，v0.7 已从 OCR 到页级写字机轨迹闭环。对无法从静态图片唯一恢复的笔顺，系统采用拒绝/重写策略，而不是宣称不存在的信息已被完美识别。

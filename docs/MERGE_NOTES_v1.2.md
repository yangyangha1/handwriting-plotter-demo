# v1.2 版本整合说明

## 整合原则

- 以 `handwriting_plotter_demo_v0.9` 作为同名文件和核心功能的基线。
- v0.8 与 v0.9 同一路径内容不一致时，保留 v0.9 的实现；这样不会回退字体导出、Web 服务、任务令牌、路径边界和批量导出能力。
- 只补入仍适用于 v0.9 入口的辅助能力，并在补入时调整旧路径引用。
- 原始 v0.8、v0.9 目录和压缩包保持不变。

## 保留与补入

- 保留 v0.9 的 `evidence/`、完整字库示例、浏览器测试、TrueType 导出和 `AUDIT_v1.2.md`。
- 补入并适配 `scripts/install_ocr_windows.ps1`，支持通过 `-Python` 指定隔离解释器。
- 保留并适配 `scripts/build_web_exe.ps1` 作为传统单文件构建工具；v1.2 默认交付的是标准库便携启动器，不把依赖冻结到旧 EXE。
- 以 v0.8 的前端结构为基础，保留逐项安装操作、步骤解锁和图片预览占位，接回 v1.0 的后端接口。
- 新增标准库便携启动器：启动时先检测 Python 3.10+，在项目目录创建 `.venv`，使用 `requirements-portable.txt` 安装依赖。
- 便携启动器把 pip、OCR 模型缓存和运行目录放到项目内，数据固定从项目 `data/` 读取，删除项目目录即可清理；Torch、PaddleOCR、GPU/CUDA 后端只做可选检查，不自动安装。
- `graphics.txt` 和 `dictionary.txt` 随源文件交付；如果文件被误删，启动器会尝试自动从 MMH 官方地址重新创建。非关键依赖或数据恢复失败只记录警告，不阻止环境检查页启动。
- 网页环境卡显示实际 Python 解释器、运行模式、每个模块的功能用途和项目虚拟环境状态；可选模块缺失只显示提示，不阻断核心流程。
- 统一包版本、Python 模块版本、Web 页面标识、字体元数据和文档标识为 1.2。

## 不纳入

- v0.8 的 `build/`、`dist/`、`__pycache__/`、测试缓存和 `egg-info/`：它们是本地生成物，且部分仍指向已替换的 `web_gui.py` 入口。
- v0.8 的 `REAL_MACHINE_VALIDATION_v0.8.md`：其中的路径、入口和构建产物均绑定旧版本，不能直接作为 1.2 验收记录。
- v0.8 的旧 Web UI、旧 GUI 入口和旧同名源码：会覆盖 v0.9 已完成的功能与安全修复。

## 验收边界

1. 1.2 的功能声明继续以 v0.9 的实测边界为准，不把少量样本实验字形描述成完整个人草书字体。
2. `evidence/` 中的实测结果保留其原始来源，属于 v0.9 基线证据；版本号统一不等于重新完成了硬件实测。
3. 1.2 交付目录不预置本地 `.venv`；便携启动器在目标目录首次运行时创建它，避免复制或污染用户主环境。
